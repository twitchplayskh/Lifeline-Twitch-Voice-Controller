Troubleshooting

Solutions for the most common problems, organised by symptom.

🔍

The 🎮 Live Feed tab is your best debugging tool. The left panel shows every chat message with command words highlighted in gold. The right panel shows every action the bot takes — Circle press, audio played, Circle release, errors. If something is not working, check what the right panel says (or does not say).

Installation Problems

pip is not recognised / Python not found

Python is not on your PATH. Re-run the Python installer from python.org and on the first screen make sure "Add Python to PATH" is ticked before clicking Install Now. Then open a new Command Prompt window and try again.

pip install fails with "Access Denied"

Try running the Command Prompt as Administrator (right-click → Run as administrator), or add --user to the install command:

pip install -r requirements.txt --user

vgamepad fails to install

Make sure ViGEmBus is installed first. vgamepad requires the driver to be present at install time. Download ViGEmBus from github.com/nefarius/ViGEmBus/releases, install it, reboot, then try pip install again.

Connection Problems

Bot shows "Failed to connect" or stays at "Connecting…"

  • Check your OAuth token — copy it again from twitchapps.com/tmi. The token must include the oauth: prefix.
  • Check your channel name has no # and is spelled correctly.
  • Check your internet connection.
  • Twitch IRC occasionally has outages — check status.twitch.tv.

Bot connects but chat messages don't appear

The bot has joined the channel but is not reading messages. This can happen if the OAuth token has expired or been revoked. Generate a fresh token and save it in settings.

Audio Problems

CABLE Input does not appear in the output device list

VB-Cable is either not installed or you have not rebooted since installing. Install VB-Cable from vb-audio.com/Cable as Administrator and reboot. If it still does not appear, click the ↻ Refresh devices button.

Commands fire (shown in log) but no audio plays

  • The output device may be set to Default instead of CABLE Input. Check Settings → Audio → Output device.
  • The volume may be at zero. Check Settings → Playback → Volume.
  • If using audio files, make sure the files exist and are named correctly. The log will show ! word (no_file) if no file was found.
  • If using TTS, check that pyttsx3 is installed: pip install pyttsx3.

Audio plays through my speakers instead of the virtual cable

The output device in Settings is set to your speakers/headphones instead of CABLE Input. Go to Settings → Audio → Output device and select CABLE Input (VB-Audio Virtual Cable).

TTS shows "tts_failed" in the log

pyttsx3 failed to synthesise audio. This happens most commonly because the pyttsx3 engine's internal COM state gets corrupted. The bot reinitialises the engine on each synthesis call to work around this, but occasional failures can still happen. The next trigger of the same command will usually succeed. If it consistently fails:

  • Run pip install --upgrade pyttsx3
  • Restart the bot
  • Try a different TTS voice in Settings → TTS → Voice

Game Not Responding to Commands

This is the most common issue and usually has one of four causes. Work through these in order:

1. Audio is not reaching PCSX2

The virtual audio routing is broken. Test it:

  1. In PCSX2, go to Settings → Audio and look for a microphone level meter
  2. Type a command in Twitch chat
  3. The meter should spike when the bot plays audio

If it does not spike: confirm the bot's output device is CABLE Input, and PCSX2's microphone input is CABLE Output. Both must be set correctly.

2. Circle is not being pressed

The virtual controller is not working. Test it:

  1. In PCSX2, go to Settings → Controllers and open the controller test
  2. Click Test Circle timing in the bot's settings
  3. The Circle button indicator should light up in PCSX2 during the test

If it does not: make sure the virtual controller is enabled in the bot, ViGEmBus is installed, and you have rebooted since installing. Try switching between DS4 and Xbox 360 mode. Make sure the virtual controller is assigned to Player 1 in PCSX2.

3. The timing is wrong

The most likely cause once audio and controller are confirmed working. The game needs Circle to be held, then a pause, then the command is spoken. If the pause is too short, the game misses it.

  • Increase Pause after press from 0.50s to 0.70s or 1.00s
  • Make sure Hold for full audio duration is ticked
  • Try adding 0.10s to Hold after audio

See Circle Button Timing for the full guide.

4. The USB Headset is not emulated in PCSX2

Lifeline requires the PS2 USB Headset device. In PCSX2, go to Settings → USB and set Port 1 to Headset/PS2 Mic with CABLE Output as the audio source. Without this, the game will not have a microphone to listen to at all, regardless of whether audio is flowing through the cable.

TTS voice not recognised by the game

The game's voice recognition was tuned for human speech, not synthetic TTS voices. Some TTS voices work much better than others. If recognition is poor:

  • Try a different voice — in Settings → TTS → Voice. Microsoft voices (Zira, David, Hazel) tend to work reasonably well.
  • Lower the speech rate to 120–130 wpm for clearer articulation
  • Record your own voice clips for the most-used commands — see Audio Files
  • Increase microphone volume in PCSX2's audio settings

Controller Problems

"Virtual controller could not be created" error

  • ViGEmBus is not installed, or you have not rebooted after installing it
  • Try switching between DS4 and Xbox 360 mode in the settings
  • Run the bot as Administrator (right-click → Run as administrator)

Chat button commands are not working

  • Make sure the virtual controller is enabled (tick the Enable checkbox)
  • Make sure the specific button row has its On checkbox ticked
  • The trigger word must match exactly — it is whole-word matched against the message
  • Save your settings after making changes
  • Check the command log — if the bot detects the trigger word it logs ▶ L1 pressed. If nothing appears, the word is not being detected.

Chat button settings reset after restart

You changed settings but did not click 💾 Save Settings before closing the bot. Settings are only persisted when you explicitly save.

Performance Issues

There is a noticeable delay between chat typing and audio playing

Some delay is unavoidable — Twitch IRC has inherent latency, and TTS synthesis adds more. To minimise it:

  • Use audio files for common commands instead of TTS — files play instantly after the first load, while TTS takes 200–500ms to synthesise
  • The TTS cache means repeated words play from cache after the first synthesis — so delay reduces after the first use of each word
  • The bot uses TCP_NODELAY on its IRC socket to remove Nagle algorithm buffering

Commands queue up and play one after another with a long delay

The playback worker serialises all commands — only one plays at a time. If chat is very active, commands can queue up. Increase the cooldown in Settings → Playback → Command cooldown to reduce how quickly the queue fills.

Miscellaneous

config.json is corrupted and the bot won't load settings

If the config file gets corrupted (e.g. power cut during save), the bot backs it up as config.json.corrupted and falls back to defaults. Delete config.json and reconfigure from scratch, or restore from the backup if it is readable.

The bot window opens but nothing happens when I type in chat

Check you are connected — the Live Feed tab should show ⬤ Live in green. If it shows ⬤ Offline, click Connect. If connection fails, see the Connection Problems section above.

Scrolling in the Settings or Commands tab scrolls both tabs at once

Move your mouse cursor fully inside the panel you want to scroll before using the mouse wheel. Scrolling is bound to whichever panel the mouse is hovering over.
